### Paseo safety and owner-only runbook

The native Paseo CLI, daemon/UI and wrappers currently do not share a verified transaction primitive. `paseo daemon config set` performs an atomic file replacement, not a cross-writer CAS; a wrapper-level lock or post-write comparison does not prevent lost updates. **No unattended native apply.** With explicit owner permission, take a private backup and operate in a quiescent Paseo home; do not run concurrent UI/CLI/daemon setting changes. The owner has explicitly accepted operator-only quiescent configuration **indefinitely** (#173 closed as *not planned*), without claiming race freedom or upstream CAS. Quiesce competing UI/daemon/CLI writers, make a private backup, apply deliberately, then verify the **whole** resulting config; if exclusivity cannot be established, refuse the write. Never roll back over a newer unrelated writer. Only reopen native CAS work if unattended native writers become an explicit requirement.

For the closed #213, the recorded disposable-home acceptance includes native writer/process/version ownership, gate-off behaviour, backup/preview/apply/readback/idempotence, denial/permission and rollback; full live-daemon password/TLS/WebSocket negative cases were explicitly accepted as untested. Routine inference/ACP/speech paths are already owner-reported working and need no redundant retest without a regression. Owner authorization is required before native config writes, private-key use, Xcode permission changes, public/tailnet listeners, cloud charges, plugin execution or Docker/process actions. No secrets or user-data exports in PR comments. Caddy may be localhost, LAN or public only under the explicitly configured exposure/auth contract; never publish local LiteLLM/oMLX/Xcode merely to make an incompatible client work. Native `PASEO_PASSWORD` must reach the *actual daemon process* to count; a value in `~/.env` is not evidence of daemon consumption.

**Deferred Paseo features:** direct Telegram/WhatsApp broker, public gateway/local engine/MCP exposure, native cross-process rollback, Basic Memory migration, embedding H2, new inference tiers, or unqualified machine-status integration. These require a concrete use case and independent owner decision.
