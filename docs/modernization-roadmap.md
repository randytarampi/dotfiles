## 1. Contract and evidence standard

This is a decision and dependency map, not permission to change model tiers, credentials, packages, account entitlements, native user state, exposure policy, CI gates or branch rules. Such changes require separate approved work. Historical results are dated evidence, never claims about the current installed host. A successful unit test, generator, deployment, protocol probe, authenticated request and user-facing operation are different levels of evidence.

- **`delivered`:** implementation merged to `main` with source/test evidence; **`ci-verified`:** the relevant exact-head required checks succeeded; **`host-verified`:** the stated installed-version operation succeeded on the intended host; **`owner-reported`:** an owner reported a test that was not independently performed here; **`partial`:** explicit remaining acceptance; **`deferred`:** a prerequisite or owner decision blocks the next step; **`superseded`:** later approved policy replaces the earlier plan; **`ongoing`:** a recurring control, not a finishable issue; **`unknown`:** no usable observation. These labels are not interchangeable and may describe different dimensions of the same work.
- **Acceptance provenance:** cite the exact PR/commit, installed versions, consumer route and operation, redacted result, CI run (if known), owner approval, rollback and failure/negative case. Do not translate an unobserved host outcome into PASS. Source/test verification here does not mean this document's edit ran `make verify`.
- **Authority:** [AGENTS.md](../AGENTS.md) and [conventions.md](conventions.md) govern repository behavior; [tiers.md](tiers.md) is the model-selection authority; [litellm.md](litellm.md) owns gateway setup; [orchestration.md](orchestration.md) owns script/gate inventory; [capability-matrix.md](capability-matrix.md) owns consumer capabilities; [paseo-security.md](paseo-security.md) owns Paseo security specifics. This roadmap does not duplicate generated inventories.

### Paseo safety and owner-only runbook

The native Paseo CLI, daemon/UI and wrappers currently do not share a verified transaction primitive. `paseo daemon config set` performs an atomic file replacement, not a cross-writer CAS; a wrapper-level lock or post-write comparison does not prevent lost updates. **No unattended native apply.** With explicit owner permission, take a private backup and operate in a quiescent Paseo home; do not run concurrent UI/CLI/daemon setting changes. The owner has explicitly accepted operator-only quiescent configuration **indefinitely** (#173 closed as *not planned*), without claiming race freedom or upstream CAS. Quiesce competing UI/daemon/CLI writers, make a private backup, apply deliberately, then verify the **whole** resulting config; if exclusivity cannot be established, refuse the write. Never roll back over a newer unrelated writer. Only reopen native CAS work if unattended native writers become an explicit requirement.

For the closed #213, the recorded disposable-home acceptance includes native writer/process/version ownership, gate-off behaviour, backup/preview/apply/readback/idempotence, denial/permission and rollback; full live-daemon password/TLS/WebSocket negative cases were explicitly accepted as untested. Routine inference/ACP/speech paths are already owner-reported working and need no redundant retest without a regression. ## 8. Update and issue hygiene rules

1. **One executable outcome per open issue.** Each must state delivered baseline, exact residual, positive and negative acceptance, permitted host scope, dependencies, evidence owner and closure criteria. Avoid keeping a completed implementation open because a different feature was appended later.
2. **Split by application family and acceptance surface, not code file.** Codex CLI #82 was closed on owner-reported daily use; ChatGPT Desktop Codex is independently #216, Claude Desktop #209, Gemini CLI #210, Hermes #217, Copilot CLI #218, Cursor CLI/Desktop #219 and VS Code #220. #83 owns only new Junie Cohere/Poolside groups. #87 policy and #211 executor are separate. 3. **Close completed or superseded work explicitly.** #84's automated Pi loader is superseded, #82 Codex CLI accepted by the owner, and #173 native CAS declined in favour of manually quiesced configuration (race still real); these are closed with recorded reasons. Operational-control #197 stays deliberately open and is excluded from completion metrics. Defer speculative work without decorative tickets.
4. **No silent deployment/document claims.** A merged PR updates `delivered`; only exact CI outcomes update `ci-verified`; an authorized installed test updates `host-verified`. Date each result, update component guides before changing broad architecture summaries and maintain issue⇄roadmap links.
5. **Change safety first:** never convert a roadmap-only edit into tier changes, destructive file edits, CI promotion, external calls or credential/secret access. Run `make check-cli-contract`, `make check-env-coverage`, `make check-hashes`, `make check-mcp-parity`, focused tests and `make verify` where applicable; report any NOT RUN honestly.
6. **Work estimates:** S = hours, M = 1–2 focused days, L = several days, XL = multi-session. Historical estimates are not time measurements; do not automatically treat all deferred items as funded work.
7. **Documented direct-to-`main` exception (2026-11-08).** Three CI-infrastructure repairs bypassed the PR flow during that session's integrated verification: executable-bit alignment `e7f83b69`, the hermetic nvm test lane `8f7340d6` (a real global `npm update` was observed running inside the offline bats test; multi-day zombie processes were found and killed) and the BSD `mktemp` portability fix `22a2439c` (a `.sh`-suffixed template intermittently failed owner-host runs that GNU mktemp CI hosts kept passing).
