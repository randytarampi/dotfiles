# Paseo speech integration — local oMLX or LiteLLM gateway

The source of truth for local speech is oMLX's inference-visible model inventory and its independent status flags. This adapter ranks **qualified** STT/TTS separately: explicit request, previously selected model (while still qualified), then pinned, favourite, and stable discovery order. It excludes known-unqualified TTS and refuses all endpoints except loopback.

Use `DOTFILES_RUN_PASEO_VOICE_SETUP=1` and `python3 scripts/configure-paseo-voice.py --probe-routes --dry-run` for an explicit local speech inference probe. Probing submits a synthetic transcription and speech request, using exact model IDs and the selected `DOTFILES_VOICE_TTS_VOICE` (default serena). No model is auto-downloaded. For direct mode (`DOTFILES_USE_LITELLM_PROXY=0`), the route is oMLX loopback. For gateway mode (`=1`), the adapter requires the distinct `clients/paseo.key`, an exact served gateway alias and successful `/v1/audio/transcriptions` and `/v1/audio/speech` probes. It never falls back to direct when the gateway fails.

Owner-only apply: `DOTFILES_RUN_PASEO_VOICE_SETUP=1 python3 scripts/configure-paseo-voice.py --probe-routes --local-vad-models-dir '/VERIFIED/absolute/Paseo/models/local-speech' --apply` writes a new private `~/.local/share/paseo/dotfiles-voice.env` with exact `STT_MODEL`, `TTS_MODEL`, `TTS_VOICE`, per-protocol keys and loopback URLs. It refuses to overwrite an existing different file or follow symlinks. The env file is **not automatically loaded** by managed/Desktop Paseo. Only a foreground daemon launch explicitly supplied this environment can use it; owner must validate their actual supervisor's secret delivery. With **v0.15.4**, provider environment variables take precedence over persisted provider selection **only when the supervised daemon actually receives them**; otherwise its persisted `features.dictation` and `features.voiceMode` govern. Review those fields and the effective requested/effective runtime providers after any authorised native change. The local VAD directory argument must be substituted with an actually discovered host path; no model-data path is created or inferred by this adapter.

Do not claim that passing a route probe demonstrates a real iPhone/iPad transcription or voice response. Verify both modes, hot restart, wrong speaker, auth rotation, and no cloud egress on the installed host before promoting any client preference. Never source this file into an unrelated global shell, commit its secret contents or copy the Open WebUI credential.

## Realtime voice: native local turn detection with direct oMLX STT/TTS (#222)

The reported 2026-11-11 phone banner, `Realtime voice is unavailable: turn-detection service is not ready`, matched a daemon that requested `voiceTurnDetection=openai` but had no matching detector. **A successful local TTS HTTP probe never proves realtime voice.**

Paseo **v0.15.4** upstream source has an independent turn-detection provider resolver (environment `PASEO_VOICE_TURN_DETECTION_PROVIDER`, default `local`) and a bundled worker-backed local Sherpa/Silero ONNX VAD provider. Upstream references: [speech-config-resolver.ts at v0.15.4](https://github.com/getpaseo/paseo/blob/v0.15.4/packages/server/src/server/speech/speech-config-resolver.ts), [local/runtime.ts](https://github.com/getpaseo/paseo/blob/v0.15.4/packages/server/src/server/speech/providers/local/runtime.ts), [Silero provider](https://github.com/getpaseo/paseo/blob/v0.15.4/packages/server/src/server/speech/providers/local/sherpa/silero-vad-provider.ts).

The generated **private** `dotfiles-voice.env` now explicitly requests **`PASEO_VOICE_TURN_DETECTION_PROVIDER=local`**, plus the required **`PASEO_LOCAL_MODELS_DIR`**. Upstream `shouldIncludeLocalProviderConfig()` does **not** count local turn detection alone when STT/TTS all use `openai`; without a local model directory (or persisted `providers.local.modelsDir`) Paseo creates no local worker and VAD remains unavailable. The adapter therefore **refuses `--apply` without an explicit absolute `--local-vad-models-dir` (or `PASEO_LOCAL_MODELS_DIR`)**, and refuses symlinked paths. Supply the resolved local-speech model directory from the installed Paseo home; do not guess or create/download model data from this tool. It continues to request `PASEO_DICTATION_STT_PROVIDER=openai`, `PASEO_VOICE_STT_PROVIDER=openai`, and `PASEO_VOICE_TTS_PROVIDER=openai` because *those* OpenAI-shaped audio endpoints point at the already-qualified **direct loopback oMLX** server. No remote turn-detection API, cloud route or replacement STT/TTS model is introduced. Setting all three providers to `local` would switch transcription and synthesis to Paseo's bundled ONNX models and is **not** this integration.
