# OpenCode

OpenCode v2.0.15 is the primary AI agent tool in this setup. Its configuration is
generated by `scripts/configure-opencode.py`, and its tiers are defined in
`configs/opencode/oh-my-opencode-slim.json`; see [docs/TIERS.md](TIERS.md) for
the full tier reference.

## Provider Presets

Three upstream presets are available in the shared registry. Definitions are
adopted from the upstream oh-my-opencode-slim docs —
[openai-preset](https://github.com/alvinunreal/oh-my-opencode-slim/blob/master/docs/openai-preset.md),
[thirty-dollars-preset](https://github.com/alvinunreal/oh-my-opencode-slim/blob/master/docs/thirty-dollars-preset.md), and
[opencode-zen-free-preset](https://github.com/alvinunreal/oh-my-opencode-slim/blob/master/docs/opencode-zen-free-preset.md) —
with local deviations noted in [docs/TIERS.md](TIERS.md):

| Preset | Providers | Observer | Fallback policy |
|--------|-----------|----------|------------------|
| `omo-slim-openai` | OpenAI, with OpenCode Zen fallbacks | Explicit (`openai/gpt-5.6-luna`) | OpenCode Zen, including paid GPT-5.6-Terra fallback |
| `omo-slim-thirty-dollars` | OpenAI + GitHub Copilot | Explicit (`openai/gpt-5.6-luna`) | OpenCode Zen, including paid GPT-5.6-Terra fallback; Copilot designer falls back to OpenCode Zen Gemini |
| `omo-slim-opencode-zen-free` | OpenCode Zen, with OpenAI fallbacks | Explicit (`opencode/mimo-v2.5-free`) | OpenAI GPT-5.6 models |

All presets define an explicit observer. `image_routing: "auto"` routes image
attachments to the observer; the hook strips them from the main conversation
and saves them to disk, so orchestrators never receive image bytes.

OpenCode Zen uses the standard `OPENCODE_API_KEY` environment variable. The
alternative is `/connect`, which stores authentication in OpenCode's
`auth.json`; a key is not required for the generated provider block. GitHub
Copilot authentication uses the `/connect` GitHub device flow.

The Zen free preset uses the currently listed `muse-spark-1.2-contributor-free`
for its multimodal orchestrator and `nemotron-3.5-lightning-free` for fixer;
these replace upstream names that are not present in the local Zen catalog.
The contributor-free tier means the upstream provider (Meta) may train on
prompts and completions, so use caution for privacy-sensitive work. Free-tier
IDs churn: `x-preview-f-free` and `hy3-free` were removed between 2026-08 and
2026-09.

## ACP Agent Verification

ACP (Agent Client Protocol) agents are configured in `~/.config/opencode/acp-agents.json` (gitignored, generated by `scripts/configure-acp-agents.py`). To verify ACP agent setup:

1. **Check config**: `cat ~/.config/opencode/acp-agents.json` — should contain `acpAgents` with entries for configured agents
2. **Check merge**: ACP agents are merged into `oh-my-opencode-slim.json` during `configure-opencode.py` — verify with `grep acpAgents ~/.config/opencode/oh-my-opencode-slim.json`
3. **Restart OpenCode**: After any ACP config change, restart OpenCode for agents to load
4. **Authenticate**: Each ACP agent requires its own auth:
   - **Copilot**: `copilot auth`; the OpenCode provider uses `/connect`
   - **Cursor**: `cursor-agent login` (browser auth via Cursor account)
   - **Claude**: `claude /login` (claude-code-acp wraps claude)
   - **Codex**: OpenAI auth (codex-acp wraps codex)
   - **Gemini**: `GEMINI_API_KEY` env var or `gemini auth`
   - **Junie**: JetBrains IDE login
   - **Antigravity**: `agy auth login` (Google Sign-In via system keyring). Then enable the bridge: set `DOTFILES_RUN_ANTIGRAVITY_ACP_SETUP=1` and `make deploy`.
   - **Pi**: `pi-acp --terminal-login` for ACP registry auth. Uses `pi --mode rpc` internally. Set `PI_ACP_ENABLE_EMBEDDED_CONTEXT=true` for richer context. Gate: `DOTFILES_RUN_PI_SETUP=1`.
   - **Cortex**: Requires Snowflake account + `SNOWFLAKE.CORTEX_USER` role + `~/.snowflake/connections.toml` + `snow` CLI. Uses `cortex acp serve -c <CORTEX_CONNECTION>`. Gate: `DOTFILES_RUN_CORTEX_SETUP=1`. Graceful skip when no Snowflake connection.

5. **Local-fallback ACP agents**: `--local` variants use the combined local model pool across configured engines. Available: `@codex--local`, `@claude--local`, `@junie--local`, and `@pi--local` (cloud tiers only). `@pi--local` uses the full `~/.pi-local` configuration generated with `DOTFILES_LOCAL_FALLBACK_PRESET` (default: `local`) passed as `--preset`, rather than a single-model stub or `--local-fallback-preset` (which would retain the cloud default model). `@gemini--local` is emitted only when the winning engine is Gemini-compatible (Ollama today); non-Ollama winners are logged and skipped. `@copilot--local` is unsupported (no native Ollama). The winning engine supplies the endpoint for the pool-driven `--local` agent. These are auto-generated by `configure-acp-agents.py` — do not set manually.

6. **Test**: In OpenCode, use `/agent <agent-name>` to invoke a specific ACP agent (e.g., `@gemini hello`, `@copilot explain this code`, `@pi help`, `@codex--local review this`)

## Configuration and plugins

ACP is retained in v2. `opencode acp` starts a private protocol server per
process; orchestration adapters continue to use the same command.

The generated `opencode.json` remains V1-shaped; OpenCode v2 normalizes it in
memory. Terminal-only plugins are registered in the global
`~/.config/opencode/cli.json`, using the [v2 schema](https://opencode.ai/v2/cli.json).

| Plugin | Version | Config location | Purpose |
|---|---:|---|---|
| `oh-my-opencode-slim` | `2.2.24` | `opencode.json` | tiers and agent orchestration |
| `@tarquinen/opencode-dcp` | `3.2.0` | `opencode.json` + `cli.json` | context compression and TUI panel |
| `@plannotator/opencode` | `0.27.18` | `opencode.json` | plan review and annotation |
| `opencode-planning-with-files` | `1.0.1` | `opencode.json` | durable planning and resumability |
| `@slkiser/opencode-quota` | `4.10.2` | `opencode.json` + `cli.json` | quota and usage surfaces |

The quota sidecar is `~/.config/opencode/opencode-quota/quota-toast.jsonc` and
`enabledProviders` is set to `"auto"`. Configuration registration is the source
of truth; plugin CLI command spelling is not relied on.

For token and cost reporting, use `opencode stats --cost`. The former Tokenscope,
voice, Vibeguard, and Meridian OpenCode plugins are not part of the v2 set.
OpenSpec remains available as the standalone `@fission-ai/openspec` CLI; its
OpenCode plugin is dropped.

OpenCode v2 does not execute configured LSP workflows. Use repository lint and
typecheck commands instead.
