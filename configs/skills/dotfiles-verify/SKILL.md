# Dotfiles Verify

Before claiming work is done in the dotfiles repo, run these checks in order. All must pass.

## 1. Format Python files

Run Black formatting on all Python files. Use the Homebrew-installed `black` binary — the `python3 -m black` module may not be available on the active Python.

```sh
black --check scripts/ scripts/lib/
```

If any files need reformatting:

```sh
black scripts/ scripts/lib/
```

## 2. Run the repo's standard verify command

```sh
make verify
```

This runs `check-cli-contract`, `check-env-coverage`, `check-hashes`, lint, and tests. It must exit 0.

## 3. Verify CLI contract has no pending entries

```sh
make check-cli-contract
```

Should show "0 pending (audit debt)". If any entries are pending, the contract is stale.

## 4. Clean Python bytecode cache

```sh
find scripts -name __pycache__ -type d -exec rm -rf {} + 2>/dev/null; true
```

Python bytecode artifacts (`__pycache__/*.pyc`) are generated by verification commands and should not appear in `git diff` output.

## Notes

- Skip these checks only for docs-only or trivially mechanical changes (whitespace, typos, renames) where verification adds no signal.
- If `make verify` fails, fix the issue before reporting success. Don't hand back work the user will immediately find broken.
- The `black` binary is at `/opt/homebrew/bin/black` on macOS. On Linux, it may be at `/usr/bin/black` or installed via `pip`. If `black` is not found, skip formatting and note it in the report.
